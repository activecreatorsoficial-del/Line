# Internet invite/response exchange

The user approved the proposed invite + response negotiation with a free public STUN service, provided there are no costs. This replaces the public-WSS prerequisite for the normal Internet mode. Nearby, its authenticated embedded WSS room, the approved English monochrome UI and two-arrow icons remain.

Flow: sender chooses Internet/files and creates an encrypted offer with a separate 12-digit temporary Internet code. Receiver pastes offer/code and generates an encrypted response. Sender imports the response. Both peers negotiate directly through WebRTC; no paid service, relay, central file storage or public room directory is configured. Cloudflare public STUN (stun:stun.cloudflare.com:3478) supplies reflexive candidates only. No billing account, API key, paid fallback, analytics or added dependency. Incoming firewall/NAT restrictions can still prevent a direct data path. The UI explains the extra response step and free external discovery before room creation.

Protocol: distinct versioned offer/answer URI prefix, bounded input/payload sizes, application-only SDP, authenticated encryption with existing PointyCastle AES-GCM and PBKDF2-HMAC-SHA256 off the UI isolate, fresh salt/nonce and random 128-bit session ID. Expiry is ten minutes, answer binds to the exact offered SDP/session/expiry, and duplicate/wrong-session/expired/malformed answers cannot replace a pending offer. ICE gathering finishes before exporting full SDP. No TURN candidates accepted or configured in this mode. Security-code comparison remains required before receiver approval; files never appear in invitations. Invitation and PIN stay in memory and must be shared privately. A copied encrypted invitation plus an 12-digit PIN is not a substitute for independent peer security-code verification.

Implementation order: bounded codec and abuse tests; shared native peer setup and offer/answer API with cancellation/expiry; English UI for response exchange; native Windows/Android regression and separate-process tests; final Windows installer/APK, payload/signing verification and updated docs. Do not alter router/firewall configuration or vendor caches. Old invitation handling remains for Nearby and existing v1 invitations. Existing automatic router code remains available to its existing tests/manual legacy paths rather than being rewritten for this feature.

Verification: focused Flutter tests for round trip, wrong PIN, tampering, expiry, oversize, SDP identity/application-only validation and answer/session binding; core cancellation and state guards; widget flows with responsive layout; native 8 MB exchanges with matching SHA-256/security codes, no room listener, and no relay candidates. STUN-specific runtime check verifies that native reflexive candidates are gathered without transferring file payload through the STUN endpoint. Physical unrelated networks remain separately unverified until a real remote participant is available.

Commands (run Flutter builds sequentially): flutter test; flutter analyze; flutter test integration_test/p2p_test.dart -d windows; emulator equivalent; explicit main.dart release builds; tools/package-windows.ps1 and tools/verify-installer.ps1.
